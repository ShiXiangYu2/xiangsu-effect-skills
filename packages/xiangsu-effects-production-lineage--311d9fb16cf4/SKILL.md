# 像塑特效制作

本包基于用户学习素材的 156 个独立视频、64 个主题，采用 lineage-skill 的采集、引用、压缩、连接、操作资产化流程。用途为制作与课程检索；不宣称完整师承训练或已取得技能认证。

## 开始使用

使用本机实际可用的 Python 解释器执行 `scripts/lifecycle.py check-sources --skill <本技能目录>`，读取检查结果。来源变化时标明版本差异，准备候选；未获用户对当前候选的明确同意，不覆盖已装版本。来源不可访问时可以使用已蒸馏资料，但告知验证限制。具体维护流程见 [维护规范](references/maintenance-policy.md)。

从 [主题索引](references/topic-index.md) 选择与本次需求相关的主题，按需读对应文件。精确依据查 [课程结构与证据](references/course_package.json)，使用 `scripts/search_course_notes.py` 和 `scripts/fetch_course_evidence.py` 搜索及定位。

## 制作流程

1. 从用户描述提取目标效果、跟踪对象、触发动作、状态变化、声音和输出形式。缺少影响方案的信息再询问；普通实现选择自行判断。
2. 将需求映射到主题证据：贴纸/美妆/形变；头部/手部/足部/图片/AR跟踪；触发条件/变量/坐标；动画/碰撞/关节；音频/识别；脚本/组件/预制件与外部软件导入。列出所需素材、组件和关键连接，引用支持的课程主题。
3. 先搭建能证明主交互的最小工程，再增加外观与音效。使用 [制作模板](references/templates.md) 明确状态、节点/组件、参数来源和验证动作。课程未给出的菜单名称、数值、代码 API 需明确标为待核对或实施推断。
4. 实际操作软件时，先确认可用的像塑应用接口和当前界面，再按可观察状态操作。没有可用操作工具时，交付可执行的工程搭建清单和素材规格，明确尚未实机执行；不得声称工程已保存、手机已测试或审核已通过。
5. 按 [交付检查](references/checklists.md) 验证可见效果、事件链、状态重置、跟踪稳定性与资源依赖。每次只修复已观察到的主要问题，复测对应交互。
6. 交付工程或搭建方案、素材清单、预览证据、已验证项和剩余事项。用户要求教学时，用一个实际制作任务说明方法，观察用户作品后反馈。

## 本地实操与审核反馈

制作参考/模板改款、设计交互或准备发布时，分别读取 [实操经验](references/local-practice.md) 与 [审核和发布前检查](references/review-preflight.md)。默认参考灵感后做自己的设计；素材原创不等于整体原创。内置预览模特截图仅作调试证据，不能直接用作发布图标。提示必须与实际输入动作和状态变化一致。来源见 [审核证据](references/review-sources.json)。

## 证据边界

- 来源目录是抖音像塑教学；不得将快手 BeyondEffects/必扬节点直接当作像塑节点。
- 文件夹含 76 个未完成下载，未进入课程包。`.txt` 和无扩展名文件按内容识别，其中可读媒体按视频处理。
- 转写可能误识别术语。画面分析为模型解释与抽样证据，不证明视频中每个步骤；请回到原始视频核对重要菜单与参数。
- 主题资产区分单一来源整理与跨来源综合，保留来源哈希和引用；实施适配明确标为推断。无证据的功能不得编造。
- 旧课程中的激励金额、审核时效和平台规范不作当前承诺。用户询问现行规则时核对官方来源。
- 包内只有蒸馏资产、必要短引文和证据指针；原始视频、完整转写、帧缓存与真实学习记录保持外部存储。

## 使用后维护

记录本次实操出现的具体失败、用户纠正和证据，准备最小优化候选、差异与验证；无需改动时不制造升级。安装或替换须展示当前候选后取得明确同意。

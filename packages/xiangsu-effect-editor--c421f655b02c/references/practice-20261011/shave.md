# 一键剃光头：先验结果，再做渐进揭示

## 技术路线与前提

头发分割只给遮罩，不能自动补出头皮、耳朵和背景。本案先核验当前版本的 Hair Eraser 内置能力，在预览确认光头结果后才制作交互；若当前版本缺失，应重新评估能力，不照抄资源 ID，也不保证能仅凭分割实现光头。

已实现的组合：Hair Eraser 持续输出光头画面，ShaveReveal 后处理按三条渐进蒙版混合原始相机与光头结果；4 秒内剃头机分三趟扫过。UI 放后处理之后的 2D 前景，否则会被算法/合成覆盖。需检查原图与算法结果的纹理绑定和坐标方向，分别验证 Progress=0、中间、1。

## 实测陷阱：材质重编译丢纹理绑定

本案重新编译 OMTL 后，_Original 回到默认纹理，预览出现错误纹理。修复是通过当前 schema 重新绑定 share://input.texture，再核对原始相机确实进入合成。该 URI 是本案已验证值，重用前查询当前材质与可用资源。不要根据编译成功推断材质参数仍保留。

旧“所有 .omtl 都是不可改二进制”的说法过度概括：区分工具生成/支持编辑的文本材质源与不透明二进制资源。按当前 MaterialAuthoring 文档使用支持的写入和编译流程；不手改未知二进制文件。

## 交互状态机

[ShaveDirector.ts](examples/ShaveDirector.ts) 是按钮修复后的案例快照，要求同节点 PostProcess.custom.material 和所有序列化对象完整绑定，不是即插即用。
- 询问：是/再想想；无人脸时提示入镜。
- 剃发：禁止重复触发确认；4 秒计时、三趟剃头机、10 个碎发对象池、进度文案。
- 结果：Progress=1、剃头机隐藏、显示“重新长回来”。
- 取消：保持原貌，允许重新选择。
- 恢复：清空粒子、计时、进度与音效状态，再回询问。
RecordStart 重置；事件监听在销毁时注销。丢脸暂停和恢复逻辑已编写，但此案例未完成真实连续出入镜验证。音效已绑定，交付录屏仅有视频轨，不能声称听感通过。

## 用户纠正：按钮被拍摄按钮挡住

“重新长回来按钮 点不到，被拍摄按钮挡住了。”这是实际宿主遮挡，不能只用编辑器能点作为通过依据。

本案 720×1280 参考画布，将询问/结果 UI 整体上移 120px，按钮屏幕高度由约82%移至72.6%，点击区域至少230×80。修复后编辑器真实点击恢复成功，手机宿主遮挡仍待用户复核。不要把72.6%或120px写成全设备安全区。

处理相似问题时：
1. 确认是宿主控件覆盖、命中区域偏移还是状态禁用。
2. 使用当前设计画布/视口及锚点换算，按钮视觉位置和 hit test 同步变化。
3. 将关键按钮移出实际拍摄控件占用区；扩大命中区时检查与相邻按钮是否重叠。
4. 真实走到结果态点击恢复，再重复确认/取消流程；带宿主控件的手机预览决定最终可用性。
本案触摸归一化坐标转中心坐标为 x=(u-0.5)*720，y=(0.5-v)*1280，仅适用这一坐标约定。

## 已知限制

长发肩部有算法模糊残留；不能靠剃头机遮挡动画声称已经修好。不同发型和转头效果需取实际样本验证。

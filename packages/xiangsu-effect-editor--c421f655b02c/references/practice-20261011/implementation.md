# 实施、恢复与验收经验

## 工程身份

用户说“空白工程”不证明工具连到空白工程。此会话第一次续做仍连到带相框的旧工程，停止误写；真正新工程需核对instance_id、generation、project_id、路径及场景资源。重开后丢弃旧GUID映射、缓存组件、mutation revision，按入口技能读取实时手册并记录原始用户消息。

## MCP与脚本

- 场景、资源、绑定通过当前全局MCP；不要绕过接口直连runtime/Gateway。
- inspect获取实际组件GUID再set_component；案例中跨调用的对象引用+component_type未正确解析，换成已查询组件ID才生效。这是故障处理经验，不否定所有新版引用语法。
- 脚本使用当前APJS装饰器/生命周期，无需臆造import。序列化引用可能晚于onStart可用；依赖未就绪时延迟初始化并幂等重试，初始化成功只执行一次。
- 材质编译后重新检查绑定，脚本编译后同时查USER运行错误。
- previewState/previewTime可供分状态检查，但模拟状态不能替代用户真实点击或自然循环；交付恢复默认运行值。
- 工具大输出截断时只读恢复身份、最新日志与执行状态；不要因没看到回执就重复创建模型/节点。

## 预览证据

针对修改选择最小充分验证：按钮修复走真实结果态点击，路线闭环覆盖一圈及接缝，深度贴合看转头。保留失败、修复、复测三者关联。

录屏命令成功仅证明文件生成。检查可解码、时长/分辨率/媒体轨，再抽帧核对内容；无音轨不能声称音频验收。宿主拍摄UI常不在编辑器录屏内，编辑器能点不等于真机安全区正确。

将模型源、导出资产和可播放预览交付到工作区输出目录，聊天使用绝对路径。写入先tmp、内容校验，再原子Move-Item -Force；不批量删除。保存工程遵循当前EffectWorkflow：本次规则不调用save_project，已明确提醒Ctrl+S，未来版本需读取当前规则，不能永久假定禁止保存。

## 维护行为检查（本次人工对照）

| 新任务场景 | 本候选应引导的动作 |
|---|---|
| 正脸猫须正常，转头悬空 | 读取mooncat，调整深度/跟踪并验侧脸，不只平移屏幕贴纸 |
| 光头结果有棋盘纹理 | 读取shave，查重编译后的原相机绑定，再验0/中间/1进度 |
| 恢复按钮在手机上点不到 | 分辨宿主遮挡，视觉/命中区一起移动，手机复核，不宣称固定高度通用 |
| 蜘蛛爬完闪回鼻子 | 读取spider，闭合控制点、弧长和跨缝切线，再录超过一圈 |
| 新工程沿用旧的c9 | 重新核验身份并inspect组件，不按历史GUID写入 |
| 请求优化技能 | 候选、来源哈希、差异、验证齐备后等当前候选明确批准 |

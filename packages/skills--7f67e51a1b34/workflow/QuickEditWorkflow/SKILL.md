# 快速编辑工作流

## 何时使用

满足任一条件就优先走这个工作流：

- agent 预估只需要少数命令就能稳定完成，通常是少量读取 + 一次小批量 `edit_by_dsl` + 一次 `capture_preview`
- 用户明确是在现有结果上“改一下”“再调一版”“微调一下”
- 目标已经存在，只需要局部修改，不需要从零重新做完整特效
- 这次修改范围明确，例如改名、挪层级、换颜色、调数值、补删组件、改父子关系

典型场景：

- 加一个立方体、球体、灯光、相机这类简单对象
- 改一个材质参数、粒子参数、Transform 数值或开关状态
- 把已有节点换个父节点
- 把材质参数、粒子参数或 Transform 数值小范围调一下
- 给已有宿主补一个组件，或者删掉多余组件
- 在上一次产物基础上做第二轮、第三轮迭代
- 在现有场景里补一个已有菜单对象，例如球体、立方体、灯光、相机或 `Screen Image`

## 不适用

切换条件见 `skills_root/SKILL.md` 工作流切换规则表。

## 边界约束

- 检索范围只限当前 sidecar workspace、当前工程和它们显式暴露出来的上下文；严禁检索 workspace 与工程之外的文件、代码、测试或 demo。
- 只要这次 `edit_by_dsl` 真正改了工程，就必须补一次 `capture_preview` 校准；`preview_asset` 只能补充资源预览，不能替代场景校准。
- 如果这次改动涉及 `2D Text`、HUD、结果页文案、提示文案或其他 2D UI，`capture_preview` 默认用 `scale: 1`，并把“是否出屏 / 裁切 / 重叠 / 和背景分离”当成必查项，而不是只看对象有没有显示出来。

## 核心原则

- 这是“先判断简单，再直接做”的工作流，不是方案设计工作流。
- 先定位最小目标，再执行最小改动。
- 能 `set` 就不要重建；能 `move` 就不要删了重建；能复用现有 GUID 就不要换一套新结构。
- 一次 `edit_by_dsl` batch 尽量只承载一个局部意图，避免把二次编辑做成整套返工。
- 如果这次小改动只是补一个已有菜单对象，优先 `query_knowledge(category="object", query="<EnglishObjectName>")` 后用一次 `edit_by_dsl(add_builtin_object)` 完成，不要拆成组件拼装。
- 如果这次小改动涉及文字颜色或 HUD 风格，先看实际截图里的背景，不要只凭“白色通常够亮”这类直觉下结论。
- 如果在定位过程中发现其实不止是“小改一下”，而是需要重新理解目标和规划方案，要立刻切到 `EffectWorkflow`，不要继续硬顶。

## 标准闭环

1. 先做一次复杂度判断：确认这次需求是否真的属于“少数命令即可完成”的简单编辑。
2. 先定位目标：`inspect`、`get_scene`、`list_resources`，只读取这次修改真正相关的对象或资源。
3. 选择最小命令：
   - 改名或层级：`set_scene_object`、`move_scene_object`
   - 调属性：`set_scene_object`、`set_component`、`set_resource_properties`
   - 补删组件：`add_component`、`delete_component`
   - 轻量重新挂载：`move_scene_object`、`set_component`
   - 补一个已有菜单对象：`add_builtin_object`
4. 执行一个小批量 `edit_by_dsl`。
5. 先做一次 `capture_preview` 校准当前编辑结果。
6. 按修改类型验证：
   - 资源面变化再补 `preview_asset`
   - 脚本改动先 `run_otsc_check`，再按需看 `get_script_logs`
   - 如果动到了 2D UI / 文案，额外检查是否完整落在屏幕内、是否和背景分离；对动态文本按最长高概率文案预留宽度，不要只看当前短文案，优先把文本临时替换成最长示例文案后再截图确认
   - 如果白字 / 黄字压在亮背景或花背景上看不清，先加深色半透明底板 / 条幅或改成更强对比色；得分弹字、连击、倒计时、胜负、结果标题这类强情绪文字，再判断要不要补现成 `ArtTextAsset`
7. 验证完成后，在最终回复中提醒用户保存工程。

## 二次编辑优化

- 如果是连续追改同一个目标，优先复用上一步已经定位出的节点、组件和资源，不要每轮都重新扫描整个工程。
- 优先改用户感知最强的那一个参数，确认方向对了再继续补小改动。
- 除非用户明确要求重做结构，否则不要因为小改动重建节点树或替换一整套资产。

# 2026-10 像塑实操经验

这些是本机实践结论，接口以当前 MCP 返回的 AGENTS.md、Skill/schema、APJS 类型为准，不能把下列例子变成永久参数规范。

## 工程连接与事实边界
- 每次核对实例与工程路径，get_project_context 后紧接着读取返回的 agents_file；新消息按手册写入 handoff。
- Scene/Graph/资源通过原生 MCP 编辑。仅按当前手册允许范围直接写 Assets 内脚本和材质。不凭本地路径推断已连接。
- 工程保存成功、本地编译通过、手机验证通过、平台相似度通过、审核上线是五类独立事实；都要记录证据，不能相互推导。
- 用户遇到 AI 次数上限时不反复等待 99% 或重试模型；查明错误，转普通跟踪/贴纸/材质路线需满足目标。静态预生成素材不能等同于每个拍摄用户的 AI 变身，也不能保证满足指定 AI 活动。

## 跟踪和实时合成
- 头饰使用真实 FaceBinding/Face Image，妆饰和贴脸纹理使用 Face Mask；不能拿固定屏幕位置冒充头部跟随。
- 场景可为实时摄影构图保留相机输入；两张固定人像不是实时双屏。原生 PostProcess 的 _MainTex 可采样相机输出，材质从当前完整验证范例起步，每次改写后等待精确源 state=succeeded 再绑定。
- 同一源重复采样同时要处理输出卡片比例、原始相机比例、裁切和转头时的边缘，不只看正脸。
- 本机案例里前景文字先渲染时被后处理重复或裁切。通过独立透明 RenderTexture 渲染可编辑 Text，再在最终合成时叠加；这是已经验证的一条路线，不是唯一方法。
- 原生 OMTL 重新导入后曾恢复纹理默认值，需要 inspect 检查并重新绑定 UI 纹理。保存后的原生文件可能为 TTEH 等二进制格式；不要当作 UTF-8 明文读改，不尝试解密。按当前官方 authoring 范例新建明文材质、编译后绑定。

## DSL与脚本
- 本机向量用当前支持的 typed value，例如 {type:"Vector2f",data:{x:15,y:4.69}}；纹理为 {type:"Resource",data:{guid:<当前注册引用>}}。先记录 import_resource 结果，使用 alias/$ref 或查询得到的注册引用；勿将返回结果里序列化包装当作直接 GUID。
- inspect 是静态编辑器事实；运行效果必须看预览。一次批次失败不能以截图当作通过，先修序列化/schema或编译错误。
- DSL Text2D 与 APJS 类名不同：运行时 getComponent("Text") as APJS.Text，再写 .text/.color。使用 @serializeProperty SceneObject 引用，按当前 schema 绑定，回查属性并用实际状态变化确认有效；“set_component 成功”不证明绑定或运行正确。
- 全局 Touch 回调需保持引用并 onDestroy 注销；切换做去抖、初始化/重置一致，必要动作避开底部录制按钮。点头与开拍等触发先查真实模板，不凭标题推断。

## 预览、性能与交付
- reset_preview 后跟踪初始化存在延迟；本机等 0.8 秒曾缺失配饰，后续等待后恢复。采用有界等待和再次观察，不把某个固定等待时长或第一张图当通用保证。
- 正脸、左右转头、靠近远离、丢脸恢复、多次交互及重启分别检查。窄卡片的大幅转头裁切如实列限制。
- 修改 shader/script 后执行合适的精确编译和运行日志检查；失败原因得到新证据时再扩大测试。
- 内置预览模特截图只能调试。本次旧建议“直接从工程预览取封面”已由审核反馈修正：发布图标还需非内置模特、授权来源、清晰取景、真实特效一致性、不透明底色及当前尺寸规则。详情见 review-preflight.md。
- 月光来信的点击两种氛围、文字同步与跟随有预览/编译证据；没有其审核通过证据。不能把它当成已证明通过审核的模板。
